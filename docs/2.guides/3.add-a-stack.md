---
title: Add a stack
description: Add a new curated stack to gitignore-sync — measured against real repositories first, then template, fingerprint, fixture and lock.
icon: lucide:circle-plus
---

A new stack is justified by evidence, not by a template site: an `audit` across
real repositories showing the same leftover lines recurring, or the tool that
writes the files listing them itself — its scaffold's own `.gitignore`, or output
it documents.

## Steps

1. **Measure the gap** — run `audit` over the repositories the stack is for, and
   note which leftovers it would absorb.

   ```bash
   gitignore-sync audit ../repo-a ../repo-b --min-files=2
   ```

   If the stack would remove one line from one file, it needs the second kind
   of evidence — the writing tool's own scaffold or documentation, in its
   spelling — or it is a project rule and belongs in that repository's free
   zone.

2. **Add the template** — a new key in the registry in `src/templates/index.ts`,
   starting at `version: 1`. Its position decides where it lands in the
   `# stacks:` line: repository stacks before the person-level ones. Write a
   comment above it saying where the lines came from — the repositories
   measured, or the scaffold or documentation followed — and what was
   deliberately left out.

3. **Check the template rules** — no line that another stack already carries, no
   bare `.vscode/` or `.idea/`, `!` exceptions only for files repositories really
   track. See [Templates](/concepts/templates).

4. **Add the fingerprint** — an entry in `src/detect.ts` with its `source`:
   `repo` for a committed marker, `machine` for something that describes one
   person. A marker that also turns up where the stack does not apply can be
   narrowed with `skip` (directories its patterns never enter) or `beside` (a
   file that must sit next to the match). A stack with no reliable fingerprint
   can still ship; it is then declared by hand.

5. **Pin the behaviour** — add a fixture pair `tests/fixtures/<name>.in` /
   `<name>.out`. `tests/fixtures.test.ts` picks it up and asserts idempotency on
   top. For a new fingerprint, add a case to `tests/detect.test.ts`.

6. **Lock the version** — run `pnpm templates:lock`, then format the lock.

   ```bash
   pnpm templates:lock
   pnpm exec oxfmt tests/templates.lock.json
   ```

7. **Update the stack tables** in the README and in `CLAUDE.md` (then copy it over
   `AGENTS.md`) — with an honest repository count, `0` included, and the source
   named where it is not the estate — and run `pnpm check`.

## Checklist

- [ ] `audit` shows the stack absorbing lines across more than one repository, or the writing tool's own scaffold or documentation lists them
- [ ] The template is a new registry key at `version: 1`, with a provenance comment
- [ ] `tests/templates.test.ts` passes: no line shared with another stack
- [ ] The fingerprint has the right `source`, or the stack is documented as hand-declared
- [ ] A fixture pair covers the stack
- [ ] `tests/templates.lock.json` contains the new version and is formatted
- [ ] The README and `CLAUDE.md` / `AGENTS.md` stack tables list it
- [ ] `pnpm check` is green
