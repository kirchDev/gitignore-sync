title: Adopt a grown .gitignore
description: Put an existing, hand-grown .gitignore under gitignore-sync without losing a line, and read what the first run reports.

---

A repository that already has a long `.gitignore` — pasted from a template site,
extended by hand for years — can be adopted in place. Nothing in it is deleted
unless a managed block provably covers it.

## Measure first

`audit` declares every shipped stack against the file and reports what would
still be left over. It writes nothing.

```bash
gitignore-sync audit .
```

The leftovers are the interesting part. Most should be genuine project rules —
paths only this repository has. A cluster of lines that looks like a tool's
output is a stack you probably want to declare, or one this binary does not ship.

## Preview the region

`init` fingerprints the repository and proposes a header. `--dry-run` prints the
report and the resulting file instead of writing it.

```bash
gitignore-sync init --dry-run
```

To decide the header yourself, skip the prompt with `--stacks=core,git,node,…`.
In a terminal, `init` asks once whether to take the whole proposal, then offers
the rest. Answering no lets you pick from scratch.

## Read the report

The first run on a grown file usually reports a lot. Each line is one of:

- **Removed lines a managed block already covers** — verbatim copies of template
  lines. They are now in the region.
- **Removed headings left pointing at nothing** — comments whose every pattern
  was absorbed. A comment block that never held a pattern stays.
- **Removed exact duplicates** — the same line twice in the free zone.
- **Different spellings** (`.idea` / `.idea/`) — reported only. git treats them
  differently, so choose one by hand if you want fewer.
- **A line that disables a block's exceptions** — usually a bare `.vscode` or
  `.idea`. Remove it: the managed block already ignores the directory's contents
  and keeps the shared files tracked. [Reconciliation](/concepts/reconciliation)
  explains why this one is a defect rather than a note.

The region is written at the top of the file. Everything else moves below it, in
its original order.

## Write it

```bash
gitignore-sync init
```

Run `gitignore-sync sync` straight afterwards: on a freshly written file it
reports that the file is already in sync. From here on, change stacks with
`edit`, `add` or `remove` — or by editing the `# stacks:` line and running `sync`.

## Result

The file now has a managed region and a free zone holding only what the
templates do not. To keep it that way, gate it in CI:
[Gate drift in CI](/guides/gate-drift-in-ci).

::callout{type="tip" title="Machine stacks need a human"}
`init --yes`, and `init` without a terminal, write only stacks proven by
committed files. Editor and platform stacks are named as skipped; add the ones
your team shares with `gitignore-sync add vscode`. See
[Detection](/concepts/detection).
::
