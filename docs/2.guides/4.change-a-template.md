---
title: Change a template
description: Change what an existing stack renders by adding a new version, never by editing a shipped one.
icon: lucide:git-compare-arrows
---

A shipped template version is immutable: repositories carry sections rendered at
it, and reconciliation reads it to tell template lines from hand-written ones.
A change is always a new version appended after the current one.

## Steps

1. **Append a version** — in `src/templates/index.ts`, add a new entry to the
   stack's array with the next version number and the full new line list. Leave
   every earlier entry exactly as it is.

   ```ts
   const registry = {
     php: [
       { stack: 'php', version: 1, lines: [/* unchanged */] },
       { stack: 'php', version: 2, lines: [/* the new set */] }
     ]
   };
   ```

2. **Say why in a comment** above the new version — what was added or dropped and
   the evidence for it. The next person deciding on `v3` needs it.

3. **Check the template rules** — the new lines must not appear in any other
   stack. See [Templates](/concepts/templates).

4. **Pin the upgrade** — add or extend a fixture pair whose `.in` holds a section
   at the old version, including a hand-written line, and whose `.out` shows it
   upgraded with that line rescued.

5. **Lock the new version** — the lock test only guards versions it already
   knows, so run the script to guard this one too.

   ```bash
   pnpm templates:lock
   pnpm exec oxfmt tests/templates.lock.json
   ```

   The diff on the lock must add lines only. A changed entry for an existing
   version means an old version was edited — undo that.

6. **Run `pnpm check`.**

After release, `sync` upgrades each section to the new version and says which
ones it upgraded; until then, `check` fails on a section still at the old one.

## Checklist

- [ ] Earlier versions are untouched; the change is a new, higher version
- [ ] A comment records why the version exists
- [ ] A fixture covers the upgrade from the previous version
- [ ] The lock diff only adds the new version
- [ ] `pnpm check` is green
