git reads a `.gitignore` in every directory, so a repository can hold many.
Every command works on one file by default — the one in the directory it is
given. `check --recursive` and `audit --recursive` walk the tree, and
`src/discover.ts` decides what each file they find is.

## How it works

Each file is classified, and only one kind is a decision:

| Kind        | Recognised by                                                                                                   | What happens                    |
| :---------- | :-------------------------------------------------------------------------------------------------------------- | :------------------------------ |
| `managed`   | it carries a `# region gitignore-sync`                                                                          | checked by `check --recursive`  |
| `keeper`    | content: a `*` plus `!.gitignore`                                                                               | skipped — it holds an empty dir |
| `framework` | path: under `storage/`, `bootstrap/cache/` or `.husky/`, or a `database/.gitignore` holding exactly `*.sqlite*` | skipped — the framework owns it |
| `plain`     | everything else                                                                                                 | measured by `audit --recursive` |

`audit --include-stubs` measures keepers and framework stubs as well. A file
without a region is never drift: `check --recursive` checks only what is already
managed.

**The scan does not walk into generated output.** Its skip list comes from two
places rather than a hand-kept list:

- **The templates.** A stack that ignores a bare directory name — `node_modules`,
  `.turbo`, `build` — is a stack whose output must not be scanned. Only a bare
  name counts: the last segment of `/public/build` would skip every `build/` in
  the tree.
- **The repository's own `.gitignore` files, inherited downwards.** A directory
  the repository ignores is generated, so the scan has no business there, exactly
  as git has none.

A directory holding its own `.git` — a submodule, a vendored checkout, an agent
worktree — is a separate repository and is skipped too.

## Why it's built this way

**Keepers by content, stubs by path.** The `*` plus `!.gitignore` idiom means the
same thing in any framework, so it is matched wherever it sits. A framework stub
needs its path, matched at any depth so `services/core/storage/logs` in a
monorepo counts as readily as a root `storage/logs`. Laravel's
`database/.gitignore` also needs its content: the path alone would claim a
repository's own file there.

**Two derived skip lists instead of one maintained one.** A hand-kept list drifts
from the templates the moment a stack is added. Inheriting the repository's own
ignores catches output no template knows about — a mutation-testing sandbox
holding full copies of the repository, for example, which otherwise multiplies
every number in the report.

**Most sub-files should not exist.** A root `.gitignore` applies recursively, so
`apps/web/.gitignore` repeating `node_modules` says nothing the root does not. A
sub-file earns its place only when a pattern must apply to one subtree and not
another. That is why neither `init` nor `sync` walks the tree. Where a package
genuinely needs its own region, point the command at it:

```bash
gitignore-sync init apps/web --stacks=node,nuxt
```
