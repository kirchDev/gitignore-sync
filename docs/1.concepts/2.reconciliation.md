Every command that renders goes through one pure function, `reconcile`. It takes
the parsed file and returns the document to write plus a list of findings. The
rules below are what make running it a second time safe, and a hundredth time
boring.

## How it works

The core is three functions that touch no filesystem:

```text
parse(text)      → Document        header, sections, free zone
reconcile(doc)   → Reconciliation  the new document, plus what changed and why
render(document) → text
```

Reading and writing files happens in `src/io.ts`, and looking at the tree in
`src/detect.ts` and `src/discover.ts`. The commands compose these parts and stay
thin. That puts the whole hard part behind a string-in/string-out seam, which is
why its tests are fixture pairs under `tests/fixtures/` rather than temporary
directories.

What `reconcile` does with a document:

- **Rescues hand-written lines.** A line inside a managed section that the
  section's own template version did not put there is moved to the free zone —
  never dropped.
- **Re-renders every declared stack** at the version this binary ships. A section
  rendered at an older version is upgraded and reported as stale.
- **Removes free-zone lines a block already covers**, verbatim, and exact
  duplicates.
- **Cleans up block by block, not line by line.** Blank lines separate blocks, and
  a comment is read as the heading for the patterns beneath it. Once a managed
  section has absorbed every pattern under a heading, the heading goes too. A
  block that was only ever a note stays, and a heading whose block still holds a
  pattern is untouched.
- **Leaves unknown stacks alone.** A header name no template ships for keeps
  whatever block it already has; this binary cannot tell a template line from a
  hand-written one there, so it changes nothing.

Two findings are reported and never acted on:

- **Equivalent spellings.** `.idea`, `.idea/`, `/.idea` and `.idea/*` are four
  different patterns to git — anchored or not, directory-only or not. They are
  listed together so a human can choose; merging them would change what git
  ignores.
- **Smothered exceptions.** A bare `.vscode` in the free zone ignores the whole
  directory, and git never descends into an ignored directory. Every
  `!.vscode/…` exception the managed block renders is then dead. This gets its
  own, louder warning, because the file is doing something other than what it
  reads like.

## Why it's built this way

**Rescue is the rule the tool stands on.** Without it a re-render is a data-loss
risk, and a tool that might delete a line is a tool nobody runs a second time —
which would make it one more fetch-and-dump generator.

**Deduplication only removes what is provably identical.** Exact string
duplicates are safe to drop. Anything looser would be guessing at git semantics,
so it is reported instead.

**Block-wise cleanup is where most of the shrinkage comes from.** A pasted
template block is mostly headings over patterns the managed region now carries.
Dropping the patterns while leaving the headings would leave a file of comments
pointing at nothing.

**Idempotence is a property, not a hope.** `render` puts exactly one blank line
between blocks, and every fixture pair is also asserted to be stable under a
second run. That is what lets [`check`](/guides/gate-drift-in-ci) fail a build on
any difference at all.
