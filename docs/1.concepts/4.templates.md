A stack is a named, versioned block of patterns. The templates are data in
`src/templates/index.ts`, shipped with the binary — nothing is fetched at run
time. `gitignore-sync list` prints what the installed binary carries.

## How it works

**Every version a stack has ever shipped stays in the registry**, ascending. A
section marker names the version it was rendered at (`php@v1`), and
reconciliation reads exactly that version to decide which lines in the section
the template put there and which a person added. The current version is the last
entry, and that is what a fresh render writes.

**A shipped version is immutable, and the rule is checked.**
`tests/templates.lock.json` records every version with its lines, and a test fails
when a locked version changes. Editing one in place therefore shows up as a diff
on the lock, which is the thing a reviewer has to be asked about. The steps are in
[Change a template](/guides/change-a-template).

**Registry order is header order — except where you spell it out.** `add`,
`remove` and `init`'s detected and prompted paths write the `# stacks:` line in
registry order — `core` first, repository stacks next, the person-level stacks
last — so the header does not churn depending on how the names arrived.
`init --stacks=` is the exception: it writes the names in the order the flag
gives them.

## Why it's built this way

**Without the history, an upgrade would rescue its own lines.** If only the
current version existed, a line dropped between `v1` and `v2` would look
hand-written in every `v1` section and be moved into the free zone on upgrade.
Dropping a very old version is still allowed, and degrades safely: reconciliation
falls back to the current template, so it rescues more than it needs to rather
than deleting something it should not.

**The rules a template obeys are not style:**

- **No line may appear in two stacks.** A repository declaring both would render
  it twice, and the equivalence report would then complain about a collision the
  tool created. `tests/templates.test.ts` enforces it.
- **Never a bare `.vscode/` or `.idea/`.** git does not descend into an ignored
  directory, which makes `!` exceptions beneath it impossible. Always `.vscode/*`
  plus targeted exceptions.
- **The `!` exceptions are measured, not guessed** — they are the files the
  repositories the templates were derived from actually track.
- **`core` holds `.DS_Store` and nothing else.** It is the anchor, not a
  catch-all. Anything tool-specific belongs in a stack someone can drop, which is
  why agent working files live in `agents` and `node_modules` in `node`.

**The stacks come from real repositories, not a template site.** Most were
derived from what a set of locally cloned kirchDev and TitusKirch repositories
actually ignore. A stack may also ship on the word of the tool that writes the
files — its scaffold's own `.gitignore` or the output it documents — which is
how `laravel` follows the Laravel skeleton, `vite` the `create-vite` scaffold and
`helm` what `helm dependency update` vendors
([ADR-0009](/adr/0009-accept-stacks-on-the-word-of-the-tool-that-writes-the-files)).
A public template site's guess never qualifies. Some choices that follow from
this look like omissions and are not:

- `composer.lock` is in no template — a library ignores it, an application
  commits it, so it is a project decision and belongs in the free zone.
- `.terraform.lock.hcl` is not ignored; it is meant to be committed.
- The JVM stack is `gradle`, not `java`: what a JVM repository ignores follows the
  build tool, and `*.jar` is left out because the Gradle wrapper jar is committed.
- `octane` uses the spellings `octane:install` appends (`frankenphp`, not
  `/frankenphp`), so re-running the installer adds nothing.
- `dist` belongs to `node` alone, because a line may live in only one stack. The
  same rule keeps `dist/` and `build/` out of `python`: a pure Python repository
  that builds wheels keeps `dist/` in its free zone.
- `helm` names only `**/charts/*.tgz`, never `charts/` itself — a bare directory
  would hide the charts a chart repository keeps there. `Chart.lock` is
  committed.

**Coverage is measured with the tool itself.** `gitignore-sync audit <dirs…>`
declares every stack against each named repository and reports what would still
be left over. A stack that would move that number by one line needs the writing
tool's own word instead, or it is a project rule — see
[Add a stack](/guides/add-a-stack).
