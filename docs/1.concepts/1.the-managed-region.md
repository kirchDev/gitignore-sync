A file maintained by gitignore-sync has two parts: a **managed region** the tool
owns and re-renders, and a **free zone** it never writes to. The region carries
its own configuration, so there is no second file.

```gitignore
# region gitignore-sync
# stacks: core, node, vscode
# ─────────────────────────────────────────

# region core@v1
.DS_Store
# endregion

# region node@v1
node_modules
dist
...
# endregion

# endregion

/bootstrap/ssr
```

## How it works

- **The header is input; the sections are output.** The `# stacks:` line declares
  what the repository wants. The `# region <stack>@v<n>` sections below it are
  what was last rendered from that declaration. A difference between the two is
  not an error, it is the pending change — `sync` applies it, `check` reports it.
- **Dropping a stack is an edit, not a verb.** Delete the name from the header and
  run `sync`; the block goes. `add`, `remove` and `edit` exist only as
  conveniences over that same one-line edit.
- **The free zone is everything outside the region.** `render` writes the region
  first and the free zone below it, so lines that sat above the region in an
  existing file end up beneath it. Every non-blank free-zone line keeps its order;
  only blank padding at the edges is normalised, which is what makes a second
  `sync` a no-op.
- **`core` is declared, not implied.** `init` always proposes it and writes it into
  the header. Removing it is then a visible change rather than a block that
  appears without anyone asking for it.

## Why it's built this way

**Detection cannot cover half the problem.** A fingerprint works for a stack —
`package.json` means `node`, `go.mod` means `go`. It cannot work for `vscode`,
`intellij` or `macos`: those describe the person working on the repository, and
nothing in the tree records them. Some declaration is unavoidable, and once one
is needed the cheapest place for it is the file being configured. A separate
config file would be one more thing to drift from the `.gitignore` it describes.

**`# region` rather than `# start` / `# end`** because VSCode folds `#region`
markers: a long managed block collapses to one line, and the nested form folds at
both levels. The version sits in the section marker (`node@v1`) so a stale block
is visible without any other state — see [Templates](/concepts/templates).

**The free zone is the user's.** A tool that rewrites lines it did not write is a
tool nobody runs twice. How a re-render stays inside its region, even when
someone edited a managed block by hand, is the subject of
[Reconciliation](/concepts/reconciliation).
