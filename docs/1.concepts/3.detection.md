Detection proposes stacks from what it finds — a `package.json`, a `.vscode/`
directory, the platform running the command. It runs at one moment only, and
not every signal it finds may be written without a human confirming it.

## How it works

**Detection changes its moment; it does not disappear.**

| Command         | Detection                                                |
| :-------------- | :------------------------------------------------------- |
| `init`          | yes — fingerprint the repository, propose the header     |
| `edit`          | shown — the prompt marks what the tree suggests          |
| `sync`          | no — read the header, render from it, nothing else       |
| `sync --detect` | suggests stacks to add to the header, never applies them |

**One detector, and a `source` on every signal.** There is one fingerprint table
and one `detect(dir)` pass in `src/detect.ts`. Each signal carries where it came
from:

- `repo` — a committed marker such as `package.json`, `go.mod`, a `*.tf` file or
  `.env.example`. It holds for everyone who clones.
- `machine` — `.vscode/` and `.idea/` (themselves usually ignored), `$VISUAL` /
  `$EDITOR`, `process.platform`. It describes one keyboard.

Both kinds are proposed together in the interactive `init` prompt. The field
decides exactly one thing: whether a signal may reach the header without
confirmation. `init --yes` and `init` without a terminal keep only `repo`
signals, then name what they skipped and how to add it back.

**Pattern fingerprints look one level below the root**, because a Terraform
repository keeps its stacks in `tofu/` rather than at the top. `examples/`,
`fixtures/`, `testdata/` and dependency directories are never descended into: a
`.tf` file shown as documentation is not a workspace.

**A fingerprint can narrow itself further.** `python` does not look inside
`docs/`, where Read the Docs, MkDocs and Sphinx keep their build requirements in
repositories with no Python of their own. `vite` counts a `vite.config.*` only
beside an `index.html` — the entry every Vite app has and a library or CLI built
with Vite does not, so those are not offered lines that point at nothing.

## Why it's built this way

**Adding a file must not rewrite someone's `.gitignore`.** If `sync` detected,
committing a `composer.json` would silently change the managed region on the next
run. Zero-config at the start, explicit and stable afterwards — so `sync` reads
the header and nothing else, and `--detect` stops at a suggestion.

**The header is committed, so a CI runner must not write to it.** A runner is
Linux with no editor directory. An unfiltered non-interactive `init` would write
`linux` into a file that then claims it for the whole team. The `repo` /
`machine` split exists for that one decision.

**A repository cannot tell you what the other contributors use**, but it can tell
you what you use. That is worth offering as a default someone confirms, which is
why machine signals are proposed at all rather than left to be typed by hand.

**`rust` matches a root `Cargo.toml` only.** A Tauri app keeps its crate under
`src-tauri/`, and that build output belongs to the `tauri` stack; matching there
would render a `/target` line pointing at nothing.
